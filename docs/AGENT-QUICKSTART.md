# Agent quickstart

One-page operational checklist for starting a task on `if_pppoe`. Full context:
[docs/TESTING.md](TESTING.md). Plugin design: [docs/plugin/README.md](plugin/README.md).

## 1. Verify lab health (3 commands)

```
ssh <LAB_HOST> 'sudo ip netns exec isp accel-cmd -H 127.0.0.1 -P 2001 show stat'
```
Expect `sessions: active: 1` (or `0` if nothing is currently dialed — either is healthy;
`active` should not be stuck on `starting`).

```
ssh <LAB_HOST> 'bridge link'
```
Expect `isp0`, `tap-client`, `tap-mpdsrv` all attached to `br-isp` and `state forwarding`.
The hardware-peer VLAN interface also present if that path has been brought up
(`PEER_VLAN=<vlan id>`).

```
ssh <LAB_HOST> 'pgrep -af qemu-system | grep -oE "name [a-z]+"'
```
Expect `name build`, `name client`, `name mpdsrv` (all three VMs up). If the lab is
supposed to be down, expect no output instead.

If any of these don't match: `make -C lab lab-down && make -C lab lab-up` before doing
anything else. Don't debug a task against a lab you haven't confirmed is healthy.

## 2. Where to write

- Driver code (Phase 1, not started yet): `sys/net/if_pppoe.c`, `if_spppsubr.c`,
  `sbin/pppoectl/`.
- Lab scripts: `lab/isp-netns/`, `lab/vm/`, `lab/peer/` (each has its own README).
- Tests: `tests/functional/*.py` (pytest+scapy), `tests/perf/*.py` (iperf3 matrix).
- Docs: `docs/`. Update `docs/TESTING.md` if you change test behavior.

**Never edit deployed copies directly** — `~/if_pppoe-lab/isp-netns/` and
`~/if_pppoe-lab/tests-functional/` on `<LAB_HOST>` are rsync targets, not sources of
truth. Edit the repo copy and redeploy (next section).

## 3. How to redeploy

```
rsync -a --delete lab/isp-netns/ <LAB_HOST>:~/if_pppoe-lab/isp-netns/
rsync -a --delete --exclude='__pycache__' --exclude='*.pyc' tests/functional/ <LAB_HOST>:~/if_pppoe-lab/tests-functional/
```
(Both happen automatically inside `make -C lab lab-up`/`lab-down`/`test-func` — manual
rsync is only for pushing a change without a full lab cycle.)

## 4. How to test

```
make -C lab test-func                          # CLIENT=mpd5 SERVER=accel by default
make -C lab test-func CLIENT=if_pppoe          # once the driver seam exists (currently pytest.skip()s)
make -C lab test-perf BACKEND=mpd5             # or if_pppoe / mpd5-tuned / plain
pytest tests/perf -q                           # unit tests, no lab/ssh needed
```
Baseline expectation on a healthy lab: `test-func` → 17 passed, 1 deselected, 2 xfailed;
`pytest tests/perf -q` → 37 passed. See `docs/TESTING.md` for what the known xfails are
(expected, not bugs to fix).

## 5. What needs review

Every task gets reviewed before it's considered done — this project's Phase 0 convention
was one implementer per task, a separate review
pass, fixes folded back into the owning commit via `fixup!` + autosquash, never a
standalone "fix" commit for something the branch itself introduced. Follow the same
pattern for Phase 1 work: don't self-approve driver code or lab changes.

## 6. What never to do

- Don't touch the lab VM host's own network bonding/netplan config, or any
  cluster/orchestration it runs, on `<LAB_HOST>`.
- Don't touch the live PPPoE client on the router under test — it's the live
  production WAN, not a lab device.
- Don't attempt root/`sudo` actions on `<DUT_HOST>` — it needs an interactive password
  this harness can't supply; surface the need to the human instead.
- Don't hand-edit `accel-ppp.rendered.conf` — it's generated by `up.sh` from the
  `accel-ppp.conf` template on every run.
- Don't `pkill`/`kill` by process name across a netns boundary — `ip netns exec <ns> pkill
  -f/-x <name>` still matches host-wide processes. Use `ip netns pids <ns>` to build a
  scoped kill list.
- Don't host VMs on the laptop/orchestrator machine — everything runs on `<LAB_HOST>`.
- Don't git add/commit unless the task explicitly asks for it.
